# Glossary

One-line definitions of the terms used across this project (lesson in brackets).

**ACID** — Atomicity, Consistency, Isolation, Durability: transaction guarantees. [05.02]
**Active-active / active-passive** — all replicas serve traffic / a standby takes over on failure. [01.03]
**Adaptive bitrate (ABR)** — player picks video quality per segment based on bandwidth. [11.09]
**Anti-entropy** — background process that finds and repairs replica differences (Merkle trees). [06.07]
**API gateway** — single entry point handling routing, auth, rate limiting. [09.01]
**Availability** — fraction of time a system serves requests successfully. [01.03]
**Back-of-the-envelope** — quick order-of-magnitude capacity estimation. [01.05]
**Backpressure** — signalling producers to slow down when consumers are overloaded. [07.04]
**Bloom filter** — compact set; "definitely not present" or "probably present". [06.06]
**Bulkhead** — isolating resource pools so one failure can't exhaust everything. [08.04]
**CAP theorem** — during a partition, choose consistency or availability. [01.04]
**Cache-aside** — app reads cache, loads from DB on miss, deletes cache on write. [04.02]
**Cache stampede** — many concurrent misses for one expired hot key hit the DB. [04.03]
**CDC (Change Data Capture)** — streaming a DB's committed changes as events. [09.03]
**CDN** — geographically distributed caches serving content near users. [04.04]
**Circuit breaker** — stops calling a failing dependency; fails fast; probes recovery. [08.02]
**Consistent hashing** — key→node mapping where resizing moves only ~1/N of keys. [03.02]
**Consensus** — nodes agreeing on values despite failures (Raft, Paxos). [06.03]
**Count-min sketch** — approximate frequency counts in fixed memory. [06.06]
**CQRS** — separate models for writes (commands) and reads (queries). [09.02]
**CRDT** — data type whose replicas always merge to the same result. [06.02]
**Dead-letter queue (DLQ)** — where messages go after repeated processing failures. [07.02]
**Denormalization** — duplicating data to avoid joins on reads. [05.01]
**Dual-write problem** — updating DB and broker/cache without atomicity. [09.03]
**Durability** — committed data survives crashes. [01.03]
**Error budget** — allowed unreliability (100% − SLO). [01.03, 10.01]
**Event sourcing** — storing state changes as an append-only event log. [09.02]
**Eventual consistency** — replicas converge if writes stop. [01.06]
**Fan-out on write / read** — push to followers' feeds at post time / pull at read time. [11.02]
**Fencing token** — monotonically increasing number that lets storage reject stale lock holders. [06.08]
**Geohash** — encoding lat/lng into a string where shared prefix ≈ proximity. [11.08]
**Gossip protocol** — peers randomly exchange state; spreads in O(log N) rounds. [06.05]
**Hedged request** — send a duplicate request if the first is slow; take the fastest. [01.02]
**Hinted handoff** — a stand-in node holds writes for a down replica. [06.01, 11.06]
**Hot key / hot shard** — a key or partition receiving disproportionate traffic. [04.03, 05.05]
**HyperLogLog** — approximate distinct counting in ~KBs. [06.06]
**Idempotency** — repeating an operation has the same effect as doing it once. [07.03]
**Isolation levels** — how much concurrent transactions can see of each other. [05.02]
**Jitter** — randomness added to retry delays to avoid synchronized retries. [08.03]
**L4 / L7 load balancing** — routing by IP/port vs by HTTP content. [03.01]
**Lamport clock** — logical counter giving a causality-consistent order. [06.02]
**Lease** — a lock that expires after a TTL unless renewed. [06.08]
**Linearizability** — strongest consistency: behaves like a single copy. [01.06]
**Little's law** — concurrency = throughput × latency. [01.02]
**Load shedding** — deliberately rejecting work to protect the rest. [07.04]
**Long polling** — server holds a request open until data is available. [02.04]
**LSM-tree** — write-optimised storage: memtable + sorted immutable files + compaction. [05.03]
**LRU / LFU** — evict least recently / least frequently used. [04.01]
**Merkle tree** — hash tree for efficiently comparing large datasets. [06.07]
**MVCC** — multi-version concurrency control; readers see snapshots. [05.02]
**Optimistic concurrency** — detect conflicts at write time via version checks. [05.02]
**Outbox pattern** — write events to a DB table in the same transaction, relay later. [09.03]
**PACELC** — if Partition: A or C; Else: Latency or Consistency. [01.04]
**Percentiles (p50/p99)** — latency below which 50%/99% of requests fall. [01.02]
**Quorum (N, R, W)** — reads/writes wait for R/W of N replicas; R+W>N overlaps. [06.01]
**Raft** — understandable consensus algorithm: leader election + log replication. [06.03]
**Rate limiting** — capping requests per client per time window. [08.01]
**Read repair** — fixing stale replicas detected during reads. [06.01]
**Replication lag** — delay before followers reflect the leader's writes. [01.06, 05.04]
**Reverse proxy** — server-side intermediary in front of backends. [03.01]
**Saga** — sequence of local transactions with compensations. [06.04]
**Service discovery** — finding healthy instances of a service dynamically. [09.01]
**Service mesh** — sidecar proxies handling networking concerns uniformly. [09.01]
**Sharding** — splitting data across machines by a partition key. [05.05]
**Single point of failure (SPOF)** — a component whose failure takes down the system. [01.03]
**SLI / SLO / SLA** — measured indicator / internal target / contractual promise. [01.03]
**Snowflake ID** — 64-bit time-sortable unique ID: timestamp | machine | sequence. [06.09]
**Split brain** — two nodes both believing they're leader. [05.04]
**SSE** — server-sent events: one-way server push over HTTP. [02.04]
**Stateless service** — keeps no client state in memory; any instance can serve any request. [01.01]
**Tail latency** — the slow end of the latency distribution (p99+). [01.02]
**Token bucket** — rate limiter allowing bursts up to bucket capacity. [08.01]
**Trie** — prefix tree; used for autocomplete. [11.04]
**Two-phase commit (2PC)** — atomic commit across participants via prepare + commit. [06.04]
**Vector clock** — per-node counters that detect concurrent (conflicting) updates. [06.02]
**Virtual nodes** — many ring positions per server for even load. [03.02]
**WAL (write-ahead log)** — append changes to a log before applying them, for crash recovery. [05.03]
**WebSocket** — persistent, full-duplex connection over TCP. [02.04]
**Write amplification** — one logical write causing many physical writes. [05.03, 11.02]
